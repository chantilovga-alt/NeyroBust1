### 1. Overview & Core Concept

- **Что делает система**: Полнофункциональный нативный Telegram-бот без зависимости от внешних webview/Mini App, реализующий авторскую систему оптимизации ЦНС от провизора **@DonDearOfficina**:
  - Единая точка входа: кнопка «🎯 Начать авторский курс» (3 последовательных этапа: ЖКТ ➔ Нейробуст на 6+ мес ➔ Фенотропил 2 мес).
  - Структурированный каталог вспомогательных препаратов с 7 обязательными пунктами для каждой позиции.
  - Комплекс тренировок с приоритетом ног (икры + приседания в отказ) и интерактивным трекером.
  - AI Супер-ассистент на базе модели Gemini (Cause-First анализ, уровни доказательности).
- **Целевая среда**: Платформа Railway (Node.js runtime, 24/7 постоянный процесс без засыпания контейнера).
- **Ключевая ценность**: Непрерывная доступность бота в Telegram в режиме реального времени, отсутствие риска падения при перезапусках сети или сбросе TLS-соединений.

### 3. Key Product Decisions & Trade-Offs

- **Решение 1: Pure Telegram Bot vs Mini App**
  - *Выбор*: 100% нативный бот на inline-кнопках и Telegram Bot API, без необходимости загрузки внешнего Mini App.
  - *Почему*: Максимальная скорость отклика, доступность на любых устройствах и операционных системах, отсутствие проблем с кэшированием браузера Telegram.
- **Решение 2: Система защиты от засыпания (Anti-Sleep)**
  - *Выбор*: Dual Keep-Alive (внутренний loopback-запрос + внешний edge-пинг Railway) + Telegram Watchdog с авто-переподключением при ошибках polling.
  - *Почему*: Облачные платформы (включая Railway) усыпляют контейнеры без входящего трафика; регулярный пинг держит сетевой стек и Node.js event-loop активными.
- **Решение 3: Токен и переменные окружения**
  - *Выбор*: Токен `8786941443:AAGpgiMyD1tBW5NhluhDf0KmKsczag2D7QI` валидирован, прописан в `.env` и готов для указания в переменных Railway.

### 5. Шаги выполнения после утверждения плана:

1. **Верификация сборки и токена**:
   - Проверить актуальность токена бота в `.env` и конфигурации сервера.
   - Выполнить сборку (`npm run build`) и удостовериться в отсутствии ошибок линтинга (`lint_applet`, `compile_applet`).
2. **Проверка настроек Railway (`railway.json`)**:
   - Убедиться, что указан `restartPolicyType: ON_FAILURE`, `healthcheckPath: /api/health` и `healthcheckTimeout: 100`.
3. **Фиксация в Git**:
   - Убедиться, что рабочая директория чиста, все файлы зафиксированы в ветке `main`.
4. **Предоставление инструкций пользователю**:
   - Предоставить готовый блок терминальных команд для отправки в GitHub (`git remote add origin ... && git push -u origin main`).
   - Предоставить краткую пошаговую инструкцию по деплою на Railway в 3 клика.
